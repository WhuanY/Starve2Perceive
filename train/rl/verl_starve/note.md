## Main Features for out MLLM RL Training 
- Think-with-Image Framework: We use the MLLM as the visual agent, Image and Text Query as Text input.
- Environment Setting for our proposed Budget-Constrain-Think-with-Image Framework: Before sending the visual agent the image into the chat history, we downscale the input image to a maximum pixels(e.g.: 16 * 16 * 28 * 28) that is predefined by B_{pix}. Usually, the first input image has low resolution and may miss details. The visual agents can request a region to zoom-in in the coarsed-grained image, but the cropping is done in the original image pixel spaces. The region cropped from the original image will still be constrained to the maximum resolution. This rule applies to every images generated by zoom-in operation

## Programming Guide
### 0. Multiturn Interaction 
**Rel paths and main functions:**
- `verl/workers/agent/parallel_env.py`  
  - `agent_rollout_loop()` — multi-turn rollout loop (generate → env.step → append obs → next turn).  
  - `execute_tool_call()` — runs `tool.execute(action_string)`, post-processes tool result into token ids + multi_modal_inputs.  
  - `ParallelEnv.step()` — filters valid actions, builds agent_inputs with `tool`, calls `execute_tool_call` per sample.  
  - `ParallelEnv.reset()` — creates one tool per prompt via `ToolBase.create(tool_name)`, calls `tool.reset(raw_prompt, multi_modal_data, origin_multi_modal_data)` and injects `seed_img` / `pixel_budget_per_image` into multi_modal_data for fixretina.
- `verl/workers/agent/envs/mm_process_engine/fixretina_tool.py`  
  - `FixRetinaTool.execute()` — parses `<tool_call>` / `<answer>`, runs focus bboxes through `zoom_in_with_coordinate_mapping`, returns obs dict with `prompt` + `multi_modal_data` (cropped images).  
  - `FixRetinaTool.reset()` — loads original image from `seed_img`, sets `self.pixel_budget_per_image` and `self.overview_scale`.  
  - `zoom_in_with_coordinate_mapping()` — maps bbox from overview to original coords, crops from original, then `constrain_image_size(..., max_pixels=self.pixel_budget_per_image)`.
- Example zoom-in tool (README): `verl/workers/agent/envs/mm_process_engine/visual_toolbox_v2.py`.

### 1. Controlling the B_{pix}
**1. Input data format (e.g. `visualprobe2fixretina.py`)**  
- **Constants:** `MAX_VIEW_PIXELS = (28*16)**2`, `MAX_PIXELS = 16384*28*28`. Overview is capped at `MAX_VIEW_PIXELS` unless compression or fallback applies.  
- **Per sample:** In `change_extra_info()` (and thus `change_row()`):  
  - `max_view_pixels` is set from `compression_ratio` (if given) or from fixretina logic: if original pixels > `MAX_VIEW_PIXELS` then `max_view_pixels = MAX_VIEW_PIXELS`, else `MAX_PIXELS`.  
  - Overview image: `overview_pil_img, scale = constrain_image_size(original_pil_img, max_pixels=max_view_pixels)`.  
  - `pixel_budget_per_image = max_view_pixels` is stored in `extra_info`; original image bytes and `scale` are stored in `extra_info['seed_img']` (`bytes`, `scale`).  
- **Row fields:** `prompt`, `images` (overview bytes), `extra_info` (includes `seed_img`, `pixel_budget_per_image`, `answer`, `question`, `options`), `env_name='fixretina'`, `reward_model`, etc. Parquet is produced with these columns.

**2. How the hyperparam B_{pix} is passed to the training pipeline**  
- **Dataset → batch:** In `verl/utils/dataset/rl_dataset.py` `__getitem__`, each row’s `extra_info` is used to set `row_dict['seed_img']` and `row_dict['pixel_budget_per_image']`. The dataloader thus exposes `seed_img` and `pixel_budget_per_image` in the batch (non_tensor).  
- **Batch → rollout:** In `verl/trainer/ppo/ray_trainer.py`, when building the generation/rollout batch, `non_tensor_batch_keys` includes `'seed_img','pixel_budget_per_image'` (see e.g. the `test_gen_batch = test_batch.pop(..., non_tensor_batch_keys=[..., 'seed_img','pixel_budget_per_image'])` and the analogous pop for train rollout). So every rollout batch carries these fields.  
- **Rollout → env/tool:** In `verl/workers/agent/parallel_env.py` `ParallelEnv.reset()`, for `tool_name == 'fixretina'`, the code pops `seed_img` and `pixel_budget_per_image` from `data_item.non_tensor_batch` and injects them into `multi_modal_data` passed to the tool’s `reset()`.  
- **Tool use of B_{pix}:** In `verl/workers/agent/envs/mm_process_engine/fixretina_tool.py`, `reset()` pops `pixel_budget_per_image` from `multi_modal_data` and sets `self.pixel_budget_per_image`. In `zoom_in_with_coordinate_mapping()`, each crop from the original image is then resized with `constrain_image_size(raw_crop, max_pixels=self.pixel_budget_per_image)`, so both the initial overview and every zoom-in are constrained by the same B_{pix} (the value coming from the data pipeline).

### 2. Reward Function Implementation
**Main scripts:**
- `verl/workers/reward_manager/prime.py` — reward manager: loads `custom_reward_function` (e.g. `compute_score`), dispatches by `reward_fn_key` (e.g. `data_source`), passes `extra_info` to the score function, aggregates `reward_extra_info`.
- `verl/utils/reward_score/fixretina_v2.py` — fixretina scoring: `compute_score()`, `is_correct()`, `_lasj()` (LLM-as-judge); uses `extra_info['question']`, `extra_info['options']` for multiple-choice / free-form.


## Dynamically Adjusting the B_{pix} to support the curriculum learning
This is unfinished and unperfect work currently. The current challenge we are facing is the `zoom-in collapse`: As training progress and questions becoming easier and easier for the visual agents, the model's policy trends is towarding using less and less zoom-in regions. Before 1 epoch, it disappears. <SeeImages:verl_starve/assets/image_0.png> We supposed this is due to the inappropriate reward design. The current design, efficiency reward, at later stage, might dominanted the reward assigning system.

To address this problem, we are considering to dynamically adjust the B_{pix} to support the curriculum learning. The idea is to start with a larger B_{pix} and gradually decrease it as the training progress. But the challenge lies for implementation.
